# Magic View

Magic View is a non-generative finishing path, separate from calibration, stacking and the manual finish editor. `magic view` accepts a validated completed gallery target/palette or standalone FITS/RGB PNG/RGB TIFF. Gallery palettes are recomposed exclusively from their real science channels. `magic render` reloads the session and checks the source SHA-256 fingerprint before producing full output. Offline execution is the default; no input pixels or local preferences leave the computer.

## Format and provenance

`output/magic/<source-digest>/<target-id>/session.json` uses `schema: 1`, `algorithm: magic-1`, canonical private source paths, input domain/transfer assumptions, native dimensions, display crop, `subject` candidates and fallback warning, measured `analysis`, candidate decisions and artifact references. Each candidate ID digests source, palette, variant, strength, recipe version and selected catalog identity. Preview branches always start from the same display baseline; strength zero is the unchanged baseline. TIFF is RGB16 *linear-light*, PNG is 8-bit sRGB. FITS float science keys and bytes are read-only. External untagged TIFF defaults to sRGB unless its canonical path matches an original variant in an adjacent validated Photonloom gallery; `--transfer linear` overrides that assumption. An indeterminate FITS domain defaults to already displayed data unless explicitly set to linear.

A standalone source generates its own offline report rather than a fake science/gallery target. When output equals the original gallery root, the named target alone receives a `magic_sessions` reference and a variant's `magic` decision reference. Separate output does not mutate the original gallery. Existing manual finish and science links remain available.

## Measured parameters and safeguards

The versioned analysis contains robust histograms, sky MAD/high-pass noise, signal SNR, clipping, unsaturated/plateau stars, measured PSF reliability, multiscale contrast, chroma and soft reusable star/halo/sky/signal/core/low-SNR/edge masks. Debug masks are bounded preview-plane binary floats plus PNG views. Missing data is recorded as `null` plus `unavailable` reasons, not a fabricated number or subject classification.

The versioned recipe derives quality `q = sqrt(clamp((median significant-signal SNR - 3)/5, 0, 1)) × measurement_confidence`, then multiplies by Natural/Enhanced/Dramatic factors `0.30/0.65/1.00` and user strength curve `s(1.4 - 0.4s)`. The catalog identity only selects bounds; it never increases `q`. Recipe data (`RecipeSpec`, version 1) allowlists operations, masks, required measurements/channels, conservative bounds and a `general-natural` fallback: general `(0.08,0.06,0.05,0.05)`, emission `(0.12,0.15,0.07,0.15)`, spiral `(0.10,0.12,0.06,0.08)`, cluster `(0.08,0.03,0.03,0.06)`, dark `(0.10,0.12,0.04,0.06)`, HDR `(0.08,0.10,0.04,0.06)` and planetary `(0.10,0.12,0.08,0.10)` for tone/detail/sharpen/color respectively. HDR additionally needs measured core range; planetary/cluster star processing needs a trustworthy PSF. `MagicDecision` version 3 records recipe version, subject/score, fallback reason, nominal/actual parameters and safety attempts. Missing reliable PSF disables sharpening; low SNR gates detail/color. Feathered star/halo/sky/core masks protect independent tone/detail/color operations. No starless subtraction/reduction is claimed; Ha/OIII does not imply SII.

`QualityReport` version 1 checks newly clipped per-channel/display pixels (≤0.1% of initially unclipped valid pixels), sky noise and high-frequency residual (≤1.2×), matched stellar FWHM (≤10% change), annular halo overshoot (≤3 sky sigma), faint-signal retention (≥95%), and mask-edge seams (≤2 sky sigma). Pre-existing clipping is reported separately. Candidate attempts use multipliers `1, .5, .25, 0` in fixed order. Undefined dependent measurements disable enhancement; safe duplicate baseline cards are labeled honestly.

Source previews are area-averaged to a maximum side of 2048 using FITS row regions, TIFF chunks and PNG rows. Native RGB processing uses one globally fitted preview-derived calibration model with absolute pixel coordinates, 512-pixel tiles and halos, disk-backed 13-byte-per-pixel scratch and a row-provider export; it does not use a blown-up PNG or independently fit each tile. Unix scratch preallocation detects insufficient storage before writing candidate tiles. A preview's evidence does not exempt full-resolution output from quality checks.

## WCS, offline identity and consent

Only undistorted RA---TAN/DEC--TAN FITS with finite CRVAL/CRPIX and nonsingular CD or PC+CDELT is trusted. SIP, PV and other distortion/projection headers are rejected. Coordinates use f64 1-based FITS centers, RA wrapping and pole-safe spherical TAN projection; corners and edge midpoints bound the image footprint. Calibrated reference frames retain their selected sharpest original WCS, but only the target-grid reference filter writes it to integrated science FITS and `ScienceArtifact.wcs`; no unverified WCS is copied from another filter. Crop shifts CRPIX for *display* coordinates without changing science pixels/headers. Existing manifests without WCS stay valid.

`data/catalog/openngc-positions.csv` derives from OpenNGC `NGC.csv` and `addendum.csv`, pinned at commit `4e2398a263de663d83f7b86be80c368c34335764`; run `python3 data/catalog/generate.py` from the repository root to regenerate. The sorted derivative contains 12,098 valid nonduplicate entries including addendum M45, J2000 positions, angular axes, morphology and aliases. [Attribution and separate CC BY-SA 4.0 data license](../data/catalog/LICENSE.OpenNGC.txt); the Photonloom code license remains MIT. Offline ranked candidates carry coverage/size and center evidence. A class is selected only at score ≥0.6 and ≥0.15 ahead of runner-up; metadata-only title evidence is at most 0.4 and never implies a measured sky position. Ambiguous identity uses the general recipe. `--catalog-online`/Advanced checkbox opts in to a bounded 5-second HTTPS SIMBAD TAP query (`TOP 100`, ≤256 KiB CSV) using only the numeric WCS footprint, never raw pixels. No WCS skips networking even if opted in; errors preserve offline results with a warning.

## Bounded search and local assistance

The phase-3 optimizer receives only measurement-scaled, recipe-bounded operator maxima. A baseline, twelve fixed-order coordinate trials (tone/detail/sharpen/color each at normalized `0`, `0.5`, `1`) and up to eight second-pass neighboring trials produce at most 21 trial slots per variant, with per-call duplicate-vector caching and deterministic lower-change tie breaks. Candidates must pass `QualityReport` before scoring. The objective is `0.6 × bounded significant-structure contrast gain + 0.4 × bounded chroma-separation gain`; improvements below three paired standard errors score zero. Missing contrast/color measurements disable dependent operators. `MagicDecision.search` version 1 records all vectors, gate failures, metric provenance, objective, and winner. Its cache key identifies source SHA-256, recipe/version, crop and requested maximum vector; the full-resolution tile validator can still back off to an unchanged baseline.

`MagicProposal` version 1 uses strict JSON: `{\"version\":1,\"recipe_id\":\"general-natural\",\"variant\":\"enhanced\",\"strength\":0.5,\"operator_scales\":{\"tone\":0.5,\"detail\":0.5,\"sharpen\":0.0,\"color\":0.4}}`. Each scale is normalized `[0,1]`, not an unbounded absolute gain. `--magic-parameters FILE` validates the allowlisted recipe, source measurements, operator capabilities and version; it excludes simultaneous `--variant`, `--strength`, `--magic-llm` and `--magic-learn`. Advanced exports the same structure. A local planner is **only** contacted with `--magic-llm` or a populated Advanced loopback URL; outbound request has an eight-second limit, redirects/proxies disabled, and includes only aggregate scalar measurements and reviewed operation names, not pixels, image paths, WCS coordinates or history. Invalid/unreachable answers return to deterministic search with a recorded warning.

`--magic-learn` or its unchecked-by-default Advanced checkbox is required to read or write `magic-preferences.json` in the `directories::ProjectDirs("io","photonloom","photonloom")` local app-data directory. After an explicit full render, a schema-1 file atomically records the last 64 selected `{class,recipe_id,variant,strength}` values, without image metadata. The most recent matching class/recipe nudges *safe* search ranking by at most 0.0001 for its selected variant. Corrupt/missing preferences emit a warning and no prior. Default CLI/browser sessions never load history. `magic reset-preferences` and Advanced reset delete only this named app-owned file.
